# Not pinned to 1.26 any more. That pin was a pip-freeze artefact: before
# a013ed73 (Apr 2025) this file was a 5 KB freeze dump carrying
# numpy==1.26.3 alongside ortools==9.10.4067 and protobuf==5.27.0, a set that
# was at least self-consistent. That commit curated the list, dropped the
# ortools and k-means-constrained pins and moved protobuf to 6.x, but left
# numpy on 1.26 -- and nothing in the tree ever required numpy 1.
#
# Four of our own dependencies now want numpy 2: k_means_constrained needs
# >=2.1.1, ortools >=2.0.2, opencv-python >=2, scipy >=2.0.0. Holding numpy at
# 1.26 meant k_means_constrained could not use its cp312 wheel and pip had to
# backtrack to compiling an old sdist. Bounded by major, because an unbounded
# floor is what made the ortools line below break the build.
numpy>=2.1.1,<3
pandas==2.2.3
scikit-learn
# Pinned because it is the package that drives numpy and ortools upward: each
# release raises those floors, and unpinned it can move the whole set without
# anything here changing. Used on the layout path -- src/groups_operations/
# split.py splits an oversized group into spread-sized chunks with min/max
# size constraints, which plain KMeans cannot express.
k_means_constrained==0.9.1
# Declared explicitly, not left to k_means_constrained: src/pipeline/select/cpsat.py
# is the default picker, and without ortools it falls back to the loop silently.
#
# Pinned exactly, and pinned together with protobuf below. Every ortools
# release constrains protobuf to a narrow window -- below 5.30 up to 9.12,
# 6.31 or later from 9.13, 6.33.1 or later from 9.15 -- so an unbounded
# `ortools>=` left pip reconciling that against a protobuf pin no release
# accepted, which is a ResolutionImpossible naming numpy and protobuf.
# 9.15.6755 is also the floor k_means_constrained 0.9.x asks for.
ortools==9.15.6755

# `select.narrator` runs the albumNarrator policy for non-wedding galleries.
# Inference only and CPU only -- no autograd, one thread per request, and the
# measured cost is 0.18 s for a 150-photo gallery at full 768-d dims. Install
# from the CPU index so the build does not pull the CUDA wheels:
#
#   pip install torch --index-url https://download.pytorch.org/whl/cpu
#
# Bounded by major. torch pins nothing we pin, so it does not participate in
# the numpy/protobuf window that the ortools line above has to sit inside.
torch>=2.0,<3
opencv-python
